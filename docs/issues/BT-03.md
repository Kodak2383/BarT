# BT-03 — Accessibility permission: honest state, honest UI

**Mode:** 👤 HITL — *you grant the permission during acceptance; I cannot do that for you*
**needs:** — · **blocks:** BT-04, BT-06

## Why
Two failures that together make the app look broken. The status is read once in `onAppear`
([SettingsView.swift:97](../../BarT/UI/SettingsView.swift:97)), so granting it and coming back still
shows "Grant permission…". And while it is missing, the Items tab shows a list of items whose names
are provably wrong ("Kontrollzentrum (3) … (11)") — worse than showing nothing (PRD §3.1).

## Slice
`AXIsProcessTrusted()` → view state → both tabs. The first end-to-end path in the app that is
honest about its own preconditions.

## Visible result
Grant the permission in System Settings, switch back to BarT: the row flips to "Granted" and the
Items tab turns from an explanation into the real list, without reopening the window.

## Done when
- Status re-checks on window activation, not just `onAppear`.
- While untrusted, the Items tab shows a `ContentUnavailableView` with a button that opens the
  system dialog — and no item list.
- Both transitions work in both directions within one open window.

## Files
`BarT/UI/SettingsView.swift`, possibly `BarT/Permissions/AccessibilityPermission.swift`

## Acceptance needs you to
Grant (and, to test the other direction, revoke) the permission in System Settings.
