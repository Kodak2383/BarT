# BT-03 — Screen recording: ask at the right moment, show the truth

**Mode:** 👤 HITL — *you grant the permission during acceptance; I cannot do that for you*
**needs:** BT-15 · **blocks:** BT-06

## Why
Rewritten 2026-09-17. The original issue was about the **accessibility** permission — which BT-15
removes entirely, because it was only ever needed to attribute items to their owning app for the
drags. What is left is screen recording, and only for the icons in the items view (PRD §3.4).

The two failures worth avoiding are the same as before, one level down: a status that is read once
and then goes stale, and a view that shows something it cannot actually know.

## Slice
Permission state → view state → items tab.

## Visible result
Grant screen recording, switch back to BarT: the icons appear without reopening the window.

## Done when
- The state re-checks on window activation, not just `onAppear`.
- Without the permission the items view says what it cannot show and offers the request — it does
  not pretend.
- The request happens the first time the items view is opened, never at launch.
- General shows the state with a way to open the system settings.

## Files
`BarT/UI/SettingsView.swift`, new permission helper (the old `AccessibilityPermission` goes with
BT-15)

## Acceptance needs you to
Grant, and ideally revoke, the permission in System Settings.
