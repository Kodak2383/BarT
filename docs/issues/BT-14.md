first honest test of the permission and Gatekeeper chain, which cannot be tested on the machine
that built it.

## Partly done 2026-09-18 — the README screenshots

Three images under `docs/images/`, captured on the maintainer's live bar with their agreement, all
window- or region-limited (`screencapture -l<windowID>` and `-R`), never the full screen:

- `menubar-collapsed.png` / `menubar-revealed.png` — the same 1440-point strip of the menu bar one
  click apart, cropped to the identical region so the visible items sit at the same x in both.
  Taken from a one-per-second capture loop rather than by timing the click, because the reveal
  collapses again after 15 seconds.
- `items-tab.png` — the settings window, sized to 620×430 so all three grids stand without a
  scroller, activated first (an inactive window photographs as grey traffic lights and a grey tab).

**Two things the capture turned up.**

The Items tab shows names, not icons, for Hidden and Always hidden until the sections have been
revealed once in that session — the -3811 limit from BT-06, seen from the user's side this time.
The README now says so in place rather than leaving a reader to wonder why their own window looks
worse than the picture.

The ASCII diagram put `«BarT»` at the right-hand end of the bar. It is not there: BarT's icon sits
inside the visible group, and everything that was in the bar before BarT stays to its right.
Corrected.

A check that failed: counting `AXImage` elements to decide whether icons had loaded. `cell()` puts
`.accessibilityAddTraits(.isImage)` on every cell, including the text fallback, so the count was 21
either way. Only the picture showed the difference.
