## Prepared 2026-09-18 — everything that does not need the maintainer

**`scripts/release.sh`** — one command from a clean tree to a shippable zip. `xcodegen` →
`xcodebuild -configuration Release` into `./build` (predictable path; `gates.sh` owns the shared
DerivedData) → `ditto -c -k --sequesterRsrc --keepParent` into `dist/BarT-<version>.zip`. `ditto`
rather than `zip`, because a `.app` is a bundle and `zip` flattens symlinks and drops extended
attributes. Prints version, size and SHA-256.

Run and verified end to end: the zip unpacks to a `BarT.app` that is ad-hoc signed
(`TeamIdentifier=not set`), and running its binary produces four passing self-tests. **The build
is `arm64` only** — `lipo -archs` says so, and the README and release notes now say it too. An
x86_64 slice would be an untested slice; there is no Intel machine here.

**`.github/workflows/build.yml`** — rewritten. The runner is now `macos-26` (Xcode 26.6, checked
against `actions/runner-images` on 2026-09-18); the old file guessed that `macos-15` might be too
old for a 26.0 deployment target, which it is. Builds Debug *and* Release, then applies the two
style rules from `gates.sh`. It deliberately does not run the self-tests: they want a real menu bar
and a screen recording grant, and a runner has neither, so a green tick would mean less than it
looks.

**`.github/workflows/release.yml`** — on a `v*` tag, runs the same `release.sh` and publishes with
`gh release create` (preinstalled on the runner; no third-party action for a one-line job) using
`docs/RELEASE-NOTES.md` as the body. Publishing is therefore one `git tag` away.

**`docs/RELEASE-NOTES.md`** — the 1.0 text, covering both things this issue asks for: the
Gatekeeper path and the permissions-on-update caveat. Also states the arm64 limit and the Items-tab
limit found while taking the screenshots.

**`project.yml`** — `CFBundleShortVersionString` 0.1.0 → 1.0.0.

Both workflow files parse as YAML and name `macos-26`. Neither has run: there is no remote.
