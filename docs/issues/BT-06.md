# BT-06 — Tracer bullet: real icons, in the list that exists

**Mode:** 👤 HITL — *screen recording permission needs your click*
**needs:** BT-03 · **blocks:** BT-07

## Why
Icon capture is the riskiest unknown in the whole plan: a new permission, an API we have not used
here, unknown cost per item. Building the whole new view on top of an unproven capture path would
mean finding out late. So: thinnest possible slice through every layer, displayed in the list that
is already there.

## Slice
ScreenCaptureKit → per-item cache → existing list row. The grid comes later (BT-07); this proves
the data flows.

## Visible result
The current item list shows each item's real icon to the left of its name.

## Done when
- Icons are captured via ScreenCaptureKit and cached per `storageKey`, fetched once per item, not
  per poll (PRD §3.2).
- The permission is requested the first time the Items view opens, with one sentence of context —
  not during the welcome window (R2-Q5).
- Without the permission the list keeps working and shows names only.
- Cost is measured and written into this issue: time for a full capture pass, and CPU while the
  window sits open.

## Files
new `BarT/Engine/ItemIconSource.swift`, `BarT/UI/SettingsView.swift`, possibly `BarT/Model/MenuBarItem*.swift`

## Acceptance needs you to
Grant screen recording once, then confirm the icons are the right ones.
