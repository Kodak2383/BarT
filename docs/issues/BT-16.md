# BT-16 — Teach the ⌘-drag

**Mode:** 👤 HITL — *whether the explanation lands is a judgement call*
**needs:** BT-15 · **blocks:** BT-14

## Why
With BT-15, arranging items becomes the user's job (PRD §3.2). Almost nobody knows macOS lets you
⌘-drag menu bar items — an app that relies on the gesture has to teach it, or it looks broken.

## Slice
Welcome window + items view + README, one explanation in three places at the right moments.

## Visible result
Someone who has never heard of ⌘-drag knows what to do within a minute of first launch.

## Done when
- The welcome window shows the gesture as a step, in one sentence plus an illustration or short
  animation: "Hold ⌘ and drag an item across the separator."
- The items view repeats it compactly where it matters — the section explanations are the place.
- The README covers it with the screenshot.
- The wording says what the separators *are*, since the user is aiming at them.

## Files
`BarT/UI/WelcomeView.swift`, `BarT/UI/SettingsView.swift`, `README.md`

## Acceptance needs you to
Read it once as if you did not know the gesture.

## Done 2026-09-17

The gesture in three places: the welcome window (a step with a drawn miniature of the bar — a
screenshot would go stale with the next appearance change), the items view (the hint above the
grids, and every section explanation now says how an item gets *into* that section), and the
README, which got a section of its own.

**Measured while writing it, and it changed the text:** a plain reveal expands only the first
separator. The second one stays 10,000 pt wide and therefore off screen, so "drag it past both ‹
separators" is impossible until the user ⌥-clicks. All three texts say so now. Every sentence names
the ‹ separator, because that is what the reader is aiming at and they have never seen one.

The README needed more than the gesture: it still described simulated ⌘-drags, an accessibility
permission and an assignment stored in `UserDefaults`, none of which has existed since BT-15.
Those passages are corrected or gone; the structure is left to BT-02.

Left alone deliberately: the licence sections in README and the about panel still say BarT contains
Ice code and that the drag technique is the most substantial part of it. That technique left with
BT-15. Whether BarT is still a derivative work decides whether it must stay GPL-3.0 — PRD §7, and
the maintainer's call, not a cleanup.
