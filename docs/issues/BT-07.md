# BT-07 — The section grid replaces the list

**Mode:** 🤖 AFK — *I can screenshot the window myself; your taste check is welcome, not required*
**needs:** BT-06 · **blocks:** BT-08, BT-10

## Why
22 near-identical rows with identical pickers read as a database table. Three grids of real icons
read as "this is my menu bar" (PRD §3.2, R3-Q2).

## Slice
UI only — the data already flows after BT-06.

## Visible result
Three labelled areas of icons instead of a text list.

## Done when
- Each section is a grid that wraps onto further rows as needed (R4-Q1) — no horizontal scrolling.
- Per-row pickers are gone; section explanations stay.
- An empty section says so and keeps its area.
- Window sizes sensibly at 8 items and at 40; the window minimum is adjusted.
- The view is **read-only** (PRD §3.3): no pickers, no menus, no drag targets. It shows where
  items sit; moving them is the user's ⌘-drag in the bar itself.
- Every icon carries an accessibility label so the view is not silent to VoiceOver.

## Files
`BarT/UI/SettingsView.swift`

## Note
Between BT-07 and BT-08 the view is mouse-only. Keep them close together, in this order: the
keyboard path (BT-08) is a floor, not a follow-up feature.

## Done 2026-09-17

The list is gone; three labelled areas of icons took its place, `LazyVGrid` with
`GridItem(.adaptive(minimum: 54))` so the cells wrap and never scroll sideways. Verified on the
live bar at the window minimum (460 pt): twenty-one items wrap onto three rows, all three sections
fit without scrolling, and the two empty ones keep their area with an "Empty" line. Beyond that the
whole stack scrolls vertically — a forty-item bar costs three more rows, not a wider window, so the
460 × 400 minimum still fits and stays.

**The accessibility label had to be fought for.** `.accessibilityElement()` plus
`.accessibilityLabel()` produced twenty-one `AXUnknown` elements with no description at all —
silent to VoiceOver, exactly what the issue forbids. `.accessibilityElement(children: .ignore)`
with `.accessibilityAddTraits(.isImage)` fixed it. Checked by walking the live accessibility tree
(`AXUIElementCopyAttributeValue`, `AXAttributedDescription`): twenty-one `AXImage` elements
reporting "WiFi", "Clock", "CPU mini", "Time Machine" and the rest. A `.help()` tooltip answers the
same question with the mouse.

Colour and legibility come from BT-06: every icon sits on a chip filled with the menu bar's own
sampled colour, because the glyphs are white whenever the bar is dark.

One item labels itself `com.apple.controlcenter` — the display name falls through to the bundle ID
when `NSRunningApplication` has no localised name. It shows up in the tooltip and to VoiceOver,
never on screen, and it is the truth about that item; left alone.

The note about BT-08 above is stale: BT-08 and BT-10 were both dropped when the view became
read-only. There is nothing to reach by keyboard in a view that cannot be acted on — what VoiceOver
needed was the labels, and it has them.
