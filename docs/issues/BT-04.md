# BT-04 — Welcome window on first launch

**Mode:** 👤 HITL — *whether the two sentences land is a judgement call*
**needs:** BT-15 · **blocks:** BT-16

## Why
BarT starts, places its icon, and does nothing. Nobody finds the settings unaided — and after
BT-15 there is something more important to explain than a permission: that arranging items is now
the user's own ⌘-drag (PRD §3.2). This issue builds the window; BT-16 writes that explanation.

## Slice
First-run detection → new window → permission request → menu entry.

## Visible result
Delete the defaults domain, launch: a window explains BarT in two sentences and offers one button.

## Done when
- Appears on first launch only (flag in `UserDefaults`), reachable afterwards from the status menu.
- Two sentences: what BarT does, and that items are arranged with ⌘-drag (detail in BT-16).
- States that updates invalidate permissions (PRD §2).
- Asks for **no** permission at all — screen recording is requested by the items view (BT-03),
  and there is no accessibility permission any more.

## Files
new `BarT/UI/WelcomeView.swift`, `BarT/App/AppDelegate.swift`

## Acceptance needs you to
Click through the real system dialog once. I can reset first-run state myself
(`defaults delete de.andreduhme.BarT`).
