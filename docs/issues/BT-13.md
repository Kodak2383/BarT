# BT-13 — Accessibility names for the two tabs

**Status:** ❌ **Dropped — the problem does not exist.** · **needs:** — · **blocks:** —

## What I claimed
That the two tabs reach the accessibility API unnamed, as "radio button 1" and "radio button 2".

## What is actually true
`.tabItem { Label("General", …) }` already sets `AXDescription` to "General" / "Items", and that is
what VoiceOver announces. Measured on the unmodified build:

```
osascript -e 'tell application "System Events" to tell process "BarT" \
  to get description of every radio button of tab group 1 of group 1 of window 1'
→ General, Items
```

## Where the mistake came from
I read `entire contents`, which names elements by `AXTitle`. A tab button has no title, only a
description — so the listing showed "radio button 1" while the name was there all along. Checking
one attribute instead of the listing would have caught it.

Kept as a record so the claim does not resurface.
