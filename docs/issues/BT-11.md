# BT-11 — Configurable shortcut

**Mode:** 👤 HITL — *a system-wide combination has to be pressed to be trusted*
**needs:** — · **blocks:** BT-14

## Why
⌃⌥⌘B is hard-wired. On a collision the settings say "already taken" and offer nothing — a dead end
for a public release. It also gives the General tab a second real setting instead of explanatory
text (R3-Q1).

## Slice
Recorder field → persistence → Carbon re-registration → live hotkey.

## Visible result
Click the field, press a combination, release: it is registered immediately and works from another
app.

## Done when
- A recorder field captures a combination and persists it.
- The hotkey re-registers live — no restart.
- A combination Carbon refuses produces a readable message and keeps the previous one.
- Reset to ⌃⌥⌘B is available.
- Exactly one shortcut (R4-Q7); ⌥-reveal stays a click gesture.

## Files
`BarT/Services/GlobalHotKey.swift`, `BarT/UI/SettingsView.swift`, settings persistence

## Acceptance needs you to
Press a few combinations, including a deliberately occupied one (⌘Space).

## Done 2026-09-18

Recorded live by the maintainer: a combination pressed into the field works from another app
immediately, ⌘Space is refused by name, a bare key is refused, and Reset appears as soon as the
shortcut differs from ⌃⌥⌘B.

**Two refusals Carbon does not make itself.** A combination without ⌃, ⌥ or ⌘ would swallow the
bare key in every app the user types in. And `RegisterEventHotKey` answers `noErr` for ⌘Space and
then never fires, because the system sees the keystroke first — so `refusal(for:)` reads
`com.apple.symbolichotkeys`, the same preference System Settings writes. Measured: ⌘Space is
entry 64 there, parameters `[65535, 49, 1048576]`. BarT is not sandboxed, so reading the foreign
domain is plain `UserDefaults`.

Its ceiling is marked in place: a shortcut another *app* holds still slips through the check and
is only caught by Carbon's status, and a system entry stored by character rather than key code
is not caught at all.

**The key name comes from the event, not from the key code.** Translating back would mean
`UCKeyTranslate` plus the current input source; the recorded event already knows what the key
prints, which is the only thing that is right on a German layout (`kVK_ANSI_Y` prints Z).

**A local event monitor, not a global one.** It sees only what is aimed at the settings window —
the window the user just clicked — and swallows it. A global monitor would want the accessibility
permission BT-15 removed, for a field that is live for two seconds. BarT installs no main menu,
so there are no key equivalents racing the monitor either.

On a refusal the previous combination is re-registered at once: there is never a moment without a
shortcut.

## Verification

`scripts/verify/BT-11.sh` writes ⌃⌥⌘K into BarT's defaults the way the recorder does, launches the
app and reads back which combination it registered — the persistence → Carbon half, which no
self-test can reach. Watched fail first (`Hotkey ⌃⌥⌘B: registered`).

`GlobalHotKey.runShortcutSelfTest()` covers the part with no keyboard in it: the ⌃⌥⇧⌘ order, both
modifier-mask conversions, and what `refusal(for:)` turns down. It also prints whether ⌘Space is
seen as system-owned — an observation about the machine, not an assertion, because that depends on
what the user has configured.
